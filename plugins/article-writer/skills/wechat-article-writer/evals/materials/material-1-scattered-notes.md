# 关于 Claude Code 用了三个月的一些零散感受

(都是我自己用过程中随手记的,顺序乱的)

- 周五晚上把一个跑了一整天的 bug 丢给它,它说不是我以为的 race condition,是上游 API 缓存策略变了——半小时定位完,我看了半小时才信
- 比 Copilot 强的地方:能进入项目、读多个文件、改 PR 后还会自己跑 test
- 但有一次它给我重写了一个我没让它动的文件,差点搞砸 demo
- 我的同事 老张 说他现在 70% 的代码是 Claude Code 写的,他自己负责剩下的 30% 「人脑只做高度判断的事」
- 价格不便宜,$20/月 的订阅,加 API 用量 50-80/月,但对比节省的时间还是划算
- 最让我惊讶的不是写代码,是它能解释为什么不这样写——「这个方案有内存泄漏风险,因为......」
- IDE 集成做得很顺手,我现在已经不太用单独的 Cursor 了
- 它会问我「你确定要删这个文件吗」这种问题,挺好的——以前 AI 工具直接就动手了
- 数据点:我个人提效 40-50%(粗估,可能高估了),周末测试时甚至能 80%(简单任务)
- 缺点:对国内的代码库(中文注释)还是会偶尔翻译成英文,有点烦
- 一个细节:它写完代码会自己 run linter,不通过会回来改——这是 Copilot 永远没有的
- 11 月发布的 4.7 版本支持 1M 上下文,这意味着可以丢一个完整的中型仓库给它

# 我想表达的核心

不是「AI 取代程序员」那种老话题。我想说的是:**AI Coding 工具已经过了「玩具」阶段,进入了「干活伙伴」阶段**。这个变化是真切的、可量化的。但很多没用上的人还不知道。

也不想吹捧 Anthropic,客观说 Cursor、Copilot 也有各自强的地方。这篇主要是基于我自己的真实体验讲。

目标读者:正在犹豫要不要试 AI Coding 的程序员、或者已经在用但还没用深的人。
